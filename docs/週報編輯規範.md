# FinTech 週報編輯規範

網站 `洞察` 頁的週報依這份規範產出；資料放在 `src/lib/content.ts` 的 `weekly`。

## 一期的樣子

- 每期 **三則**，一則只講一件事。三則之間要有一條看得出來的線（例如同一個主題、同一條法規），寫成 **本期一句話**（`lede`）。
- 至少一則跟台灣直接相關（金管會、央行、本地業者的公開資料）。
- 封面三則短標（`headlines`）各 ≤ 12 字，只放主詞與數字。

## 一則的固定結構

| 欄位 | 內容 | 長度 |
|---|---|---|
| 標題 `title` | 事實句：誰、做了什麼、多少 | 一行 |
| 一句話 `lede` | 發生了什麼，含日期與來源機構 | ≤ 60 字 |
| 重點 `facts` | 關鍵數字與事實，每條一件事，數字要能在來源找到 | 2–4 條，每條 ≤ 40 字 |
| 為什麼重要 `why` | 這件事改變了什麼；不寫預測、不寫「值得關注」 | 1–2 句 |
| 台灣視角 `taiwan` | 台灣現況或對讀者（學生）的具體意義 | 1–2 句 |
| 名詞 `term` | 只在第一次出現、且讀者可能不懂時才寫 | 一行，可省略 |
| 來源 `sources` | 一手來源優先（新聞稿、主管機關公告）標 `primary` | ≥ 1 |

閱讀設計：10 秒看標題與一句話，1 分鐘看重點，想深入再看後兩段。

## 不寫的東西

- 沒有來源的數字、沒公布的時程（寫「尚未公布」）。
- 預測、評價式形容詞、口號。
- 備註式文字（「本期由…整理」之類）。
