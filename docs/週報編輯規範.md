# FinTech 週報編輯規範

網站 `洞察` 頁的週報依這份規範產出；資料放在 `src/lib/content.ts` 的 `weekly`。

## 一期的樣子

- 每期 **三則**，一則只講一件事。三則之間要有一條看得出來的線（例如同一個主題、同一條法規），寫成 **本期一句話**（`lede`）。
- 至少一則跟台灣直接相關（金管會、央行、本地業者的公開資料）。
- 封面三則短標（`headlines`）各 ≤ 12 字，只放主詞與數字。

## 一則的固定結構

| 欄位 | 內容 | 長度 |
|---|---|---|
| 標題 `title` | 事實句：誰、做了什麼、多少 | 一行 |
| 一句話 `lede` | 發生了什麼，含日期與來源機構 | ≤ 60 字 |
| 重點 `facts` | 關鍵數字與事實，每條一件事，數字要能在來源找到 | 2–4 條，每條 ≤ 40 字 |
| 背景 `context` | 這件事之前發生什麼：公司是做什麼的、前一步是什麼、同業在做什麼；每一句都要能在來源找到 | 2–4 句 |
| 說法 `quote` | 一手來源裡的一句原話＋誰說的（新聞稿、主管機關公告、當事人貼文）；沒有就省略，不要自己編 | 一句 |
| 為什麼重要 `why` | 這件事改變了什麼；有分析師或第三方的看法可以引，要註明是誰 | 2–3 句 |
| 台灣視角 `taiwan` | 台灣現況（法規、業者、數字）或對學生讀者的具體意義 | 2–3 句 |
| 接下來看什麼 `watch` | 具體、可查證的下一個事件（誰、什麼決定、大約何時），不是預測 | 1–2 條 |
| 名詞 `term` | 只在第一次出現、且讀者可能不懂時才寫 | 一行，可省略 |
| 來源 `sources` | 一手來源優先（新聞稿、主管機關公告）標 `primary` | ≥ 1 |

閱讀設計：10 秒看標題與一句話，1 分鐘看重點，三分鐘看完整則。

## 文字怎麼寫（去 AI 味）

照 `humanizer-zh` 技能的清單檢查，特別是這幾條：

- 不用「不是 A，而是 B」「不只 A，更是 B」的句型。
- 不用「標誌著」「凸顯」「格局」「關鍵時刻」「值得關注」這類詞。
- 少用「」框概念；一句話裡不要塞三個並列。
- 句子長短要有變化。可以用短句。
- 有具體的公司名、人名、數字、日期就寫出來，不寫「業界人士」「專家認為」。
- 說法欄要是真的有人說過的話（翻譯可以，改寫不行）。

## 不寫的東西

- 沒有來源的數字、沒公布的時程（寫「尚未公布」）。
- 預測、評價式形容詞、口號。
- 備註式文字（「本期由…整理」之類）。
