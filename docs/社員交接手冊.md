# 社員交接手冊：官網與後台怎麼用

> 這份是寫給**社團幹部**看的，不需要任何程式背景。
> 讀完你會知道：怎麼登入後台、怎麼更新官網每一種內容、發布後多久上線、出問題怎麼辦、換屆怎麼交接。
> 另一份 `docs/後台使用說明.md` 是精簡版速查表；這份是完整教學。

---

## 一、先搞懂這套東西是怎麼運作的

用一個比喻：**官網是一本印好的雜誌，後台是編輯部。**

- 你在後台（編輯部）改內容，按「發布」。
- 系統會自動「重新印一版雜誌」（我們叫**重建**），大約 **2 分鐘**。
- 印好後，官網自動換成新版。訪客永遠看到的是印好的那一版，所以官網很快、很穩定，也不會被「編輯到一半」的內容影響。

所以有兩件事要記住：

1. **按了發布不會立刻看到**，等 2 分鐘再重新整理官網。
2. **沒發布的東西（草稿）永遠不會出現在官網**，可以放心慢慢填。

## 二、第一次登入

1. 開後台網址，按「**使用 Google 登入**」，選你自己的 Google 帳號（學校信箱或個人 Gmail 都可以）。
2. 如果看到「**這個帳號沒有權限**」：代表你的 email 還沒被加進管理員名單。請已經有權限的幹部（通常是社長）到後台「管理員」頁把你的 email 加進去，然後你重新登入一次。
3. 登入後看到「總覽」頁，左邊（手機是上方選單）列出所有可以編輯的類別。

> 每位管理員權限都一樣，沒有分等級。所以**不要把自己的 Google 帳號借給別人登入**，要給誰權限就直接加他的 email。

## 三、每個畫面共通的操作

不管哪一類，操作都是同一套：

```
清單頁 → 「新增…」或某一列的「編輯」 → 填表 → 「存草稿」或「發布」
```

| 按鈕 | 意思 |
|---|---|
| **存草稿** | 只存在後台，官網看不到。清單上會標「草稿」。**只有新項目可以存草稿**，已經上線的東西一改就是改正式版。 |
| **發布** | 送上官網。已上線的項目按發布時會先問一次「這會直接上線」，確認後才送出。 |
| **刪除** | 從官網拿掉。不是真的消失，「已刪除」頁可以還原（還原後要再發布一次才會回到官網）。 |
| **拖曳左邊把手** | 調整順序（合作對象、專案）。放開就存好，官網照這個順序。 |

**中英文都要填才能發布。** 官網有中／英切換，所以每個文字欄位都有中文和英文兩格；缺的會標紅並告訴你是哪一格。英文不用寫得很文學，通順就好。

**發布之後**畫面會出現「已送出重建，約 2 分鐘後上線」，接著自動變成「重建完成」或「重建失敗」。「重建完成」就去官網重新整理確認。

## 四、各類內容怎麼填

### 1. 週報（FinTech 週報）

官網首頁顯示最新 3 期，洞察頁有全部。

**流程：**

1. 「週報」→「**新增一期**」，系統會自動帶好**下一期的期數與日期**，不用自己算。
2. 用週報 Prompt 產出這一期的內容（**Prompt 必須改成輸出 `docs/週報貼上格式.md` 的格式**，不是以前的自由格式）。
3. 把整份產出貼進「**貼上整份週報**」框，按「**拆解**」。系統會把三則新聞的標題、重點、背景、來源…自動填進對應欄位。
4. 缺的欄位會標黃，補齊。常見缺的是英文標記那幾格。
5. 按「發布」。

每一期固定是「本期一句話」＋三則新聞；每則有短標（≤12 字，首頁小卡用）、標題、一句話、重點、背景、說法、為什麼重要、台灣視角、接下來、名詞（可省略）、來源。欄位意義見 `docs/週報編輯規範.md`。

### 2. 活動（講座／工作坊／英語讀書會）

- 先選**類型**，表單會依類型顯示不同欄位：講座填講者與簡介；工作坊填目標與模組；讀書會填書名、作者、書封、簡介。
- **讀書會的書會自動出現在資源頁的「書單」**，不用另外去資源頁加。
- 填「週次」與「日期」，官網行事曆照日期排。
- **官網只顯示「目前學期」的活動**（目前學期在「學期設定」裡）。清單右上角可以切換學期，所以下學期的活動可以先建好、先存草稿，等學期設定切過去就會出現。
- 「計入出席獎勵」開關：勾了的活動會算進出席獎勵金的場次。

### 3. 資源（職缺／獎學金／計畫）

- 選類型（職缺／獎學金／計畫）後填標題、單位、說明；「細項」一行一條（工作內容、條件、金額…），可留空。
- 「**截止日**」選填。填了的話，**到期那天之後官網自動下架**，不用手動刪；清單會標「已過期」提醒你。
- 連結一定要 `https://` 開頭；「聯絡方式」填 email 或電話，可留空。

### 4. 專案

- 「**網址代號**」只能小寫英文、數字、連字號（例如 `wallet-2026`），**發布後不要再改**，改了舊網址就失效。
- 封面圖直接上傳，系統會自動縮小。
- 四張投影片是固定的：**痛點 → 解法 → 產品 → 影響**，每張選一種視覺（圖片、流程、數字、清單）並填內容。
- 清單可拖曳排序；**首頁只顯示前 3 個**，專案頁顯示全部。

### 5. 洞察文章

這是**社團自己做研究之後寫的長文**，不是貼別人的論文連結。每篇文章在官網有自己的頁面：`/insights/網址代號/`。

- 「網址代號」規則同專案，發布後不要改。
- 「摘要」一句話，會顯示在洞察頁的卡片與文章開頭。
- 「**內文**」可以用簡單的排版符號（不會的話，純文字、段落間空一行也完全可以）：

  ```
  ## 小標
  這是一段文字，**這幾個字會變粗體**，這是[連結文字](https://example.com)。

  - 清單第一點
  - 清單第二點

  > 這一段會變成引言框
  ```

- **英文內文可以留空**：英文模式下會顯示中文內文（標題、摘要仍需英文）。
- 封面圖選填；標籤可以多個。

### 6. 合作對象

- 填名稱、連結，上傳 logo（選填）。
- 「**Logo 已含名稱**」：logo 圖本身已經有公司名的話打開，官網就不會再重複顯示一次文字。
- 拖曳排序＝官網跑馬燈的順序。

### 7. 學期設定

學期代號（例如 `115-1`）、社課日、招募時程四段日期、社費、出席獎勵金級距、常見問題、繳費方式。

- **這一頁沒有草稿，按儲存就是發布。**
- 改「學期代號」會直接影響官網顯示哪個學期的活動，換學期時記得先把新學期的活動建好再切。

## 五、換屆交接清單

新舊社長交接時照著做：

1. 新社長用自己的 Google 帳號登入後台（舊社長先把他加進「管理員」）。
2. 新社長到「管理員」頁：把新一屆幹部的 email 全部加入。
3. 把已離任的幹部按「移除」（**不能移除自己**，所以最後由新社長移除舊社長）。
4. 到「學期設定」更新學期代號、招募時程、社費。
5. 把這份手冊、`docs/週報貼上格式.md`、`docs/週報編輯規範.md` 傳給新幹部。

**社團共用帳號（`nccufintechlab@gmail.com`）**：官網背後的三個服務（GitHub＝放網站程式的地方、Supabase＝存後台資料的資料庫、Google Cloud＝Google 登入用）都綁在這個 Gmail 上。它的密碼由社長保管、交接時一併交給下一任，**平常編輯內容完全不需要用到它**，只有找工程師處理問題時才會用。

## 六、出問題怎麼辦

| 狀況 | 怎麼處理 |
|---|---|
| 登入後說「沒有權限」 | 請有權限的幹部到「管理員」加你的 email，確認拼字沒錯。 |
| 後台第一次開很慢（10 秒以上） | 正常。資料庫閒置一陣子會「睡著」，第一次喚醒比較慢，之後就快了。 |
| 按了發布，2 分鐘後官網還沒變 | 先用瀏覽器「強制重新整理」（Mac：Cmd+Shift+R；Windows：Ctrl+F5）。再看後台總覽的重建狀態是不是「完成」。 |
| 重建狀態顯示「失敗」 | 通常是暫時性的（網路或服務短暫出錯）。隨便找一項按「發布」再觸發一次；連續失敗兩次就截圖總覽頁給工程師。 |
| 發布時有欄位標紅 | 那格是必填或格式不對（常見：英文沒填、連結沒有 https://、日期格式）。照提示補。 |
| 不小心刪掉了 | 「已刪除」頁找到它按「還原」，再按「發布」。 |
| 上傳圖片沒反應 | 只接受圖片檔（PNG、JPG、SVG）。PDF 或其他檔案會被拒絕。 |
| 官網整個打不開 | 這跟後台無關，看 https://www.githubstatus.com/ 是否有故障；通常等一下就好。 |

**找工程師時請附上**：你做了什麼、哪一頁、螢幕截圖、大概幾點。

## 七、不要做的事

- 不要把自己的 Google 帳號給別人登入後台。
- 不要改已發布專案／文章的「網址代號」。
- 不要在後台以外的地方（GitHub、Supabase）動手改資料，那些是工程師的區域。
- 週報 Prompt 產出的格式跟 `docs/週報貼上格式.md` 不一樣時，改 Prompt，不要手動一格一格貼——會很痛苦而且容易漏。

## 附錄：這套系統的技術面（給工程師或好奇的人）

- 官網是「靜態網站」（預先產好的一堆網頁檔），放在 GitHub Pages，免費。
- 後台資料放在 Supabase（免費方案的雲端資料庫），只有管理員名單裡的 Google 帳號能寫入。
- 按「發布」會叫 GitHub 重新產一次網站，產完自動更新，約 2 分鐘。
- 完整技術文件：專案根目錄的 `README.md`、`STATUS.md`、`HANDOFF.md`，設計決策在 `docs/specs/2026-09-14-admin-cms-design.md`。
