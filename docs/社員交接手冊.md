# 官網後台怎麼用（交接給幹部）

這份是我寫給接手官網的幹部看的。不用懂程式，照著做就好。
看不懂的地方直接問我，或找工程師。

官網：https://hunter20041004.github.io/ftl-web-demo/
後台：https://hunter20041004.github.io/ftl-web-demo/admin/

---

## 先講最重要的三件事

1. 後台改完按「發布」，官網大概 2 分鐘後才會變，不是馬上。等一下再重新整理。
2. 存草稿的東西官網看不到，可以慢慢填。
3. 每個東西都要填中文跟英文，不然發不出去。英文通順就好，不用很厲害。

---

## 登入

開後台，按「使用 Google 登入」，用你自己的 Google 帳號。

跳出「這個帳號沒有權限」的話，代表你的 email 還沒被加進去。找已經有權限的人（通常是社長）去「管理員」頁把你加進去，再登入一次就好。

大家的權限都一樣，沒有分大小。所以不要把帳號借人，要給誰用就直接加他的 email。

---

## 每一頁都是同一套操作

清單 → 按「新增」或「編輯」→ 填表 → 「存草稿」或「發布」

- 存草稿：只有新的東西可以存草稿。已經上線的東西一改就是改正式版。
- 發布：已上線的東西再按發布會多問你一次「這會直接上線」，確認就送出。
- 刪除：不是真的刪掉，到「已刪除」頁可以還原。還原後要再發布一次。
- 合作對象跟專案可以拖左邊的把手排順序，放開就存好了。

發布後畫面會跳「已送出重建」，等它變「重建完成」再去官網看。

## 各類內容

### 週報

首頁放最新 3 期，洞察頁有全部。

1. 「週報」→「新增一期」，期數跟日期會自動帶好，不用算。
2. 用週報 Prompt 產這一期的內容。**Prompt 要改成輸出 `docs/週報貼上格式.md` 那個格式**，以前的自由格式不能用。
3. 把整份貼進「貼上整份週報」，按「拆解」，欄位會自動填好。
4. 缺的欄位會標黃，補一補。
5. 發布。

一期固定是「本期一句話」加三則新聞。每則欄位的意思看 `docs/週報編輯規範.md`。

### 活動

- 先選類型（講座／工作坊／讀書會），欄位會跟著變。
- 讀書會的書會自動出現在資源頁的書單，不用再去資源頁加一次。
- 官網只顯示「目前學期」的活動（學期在「學期設定」那頁）。清單右上角可以切學期，下學期的可以先建好存草稿。
- 「計入出席獎勵」打開的活動會算進出席獎勵金的場次。

### 資源

- 職缺／獎學金／計畫。
- 有截止日的填上去，過期會自動從官網下架，不用手動刪。清單會標「已過期」。
- 連結要 https:// 開頭。

### 專案

- 「網址代號」只能小寫英文、數字、減號，**發布之後不要改**，改了舊網址就壞了。
- 封面圖直接上傳，會自動縮。
- 四張投影片固定是：痛點、解法、產品、影響。每張選一種視覺（圖片／流程／數字／清單）。
- 首頁只放前 3 個，順序用拖的。

### 洞察文章

這是我們自己做研究之後寫的長文，不是貼別人的論文。每篇會有自己的網址。

- 網址代號規則跟專案一樣，發布後不要改。
- 摘要一句話，會出現在卡片上。
- 內文純文字、段落間空一行就可以。想排版的話可以用：

  ```
  ## 小標
  **粗體**、[連結文字](網址)
  - 清單
  > 引言
  ```

- 英文內文可以空著，英文模式會直接顯示中文內文。

### 合作對象

- 名稱、連結、logo。
- logo 上面本來就有公司名的話，把「Logo 已含名稱」打開，官網就不會再寫一次。
- 順序用拖的，就是官網跑馬燈的順序。

### 學期設定

學期代號、社課日、招募時程、社費、出席獎勵金、常見問題、繳費方式。

這頁沒有草稿，按儲存就上線。改學期代號會直接影響官網顯示哪個學期的活動，換學期前先把新學期的活動建好。

## 換屆

1. 舊社長先把新社長的 email 加進「管理員」。
2. 新社長登入，把新一屆幹部全部加進去。
3. 把離任的按「移除」。不能移除自己，所以舊社長最後由新社長移除。
4. 「學期設定」更新學期代號、招募時程、社費。
5. 這份文件、`docs/週報貼上格式.md`、`docs/週報編輯規範.md` 傳給新幹部。

社團 Gmail（nccufintechlab@gmail.com）綁著官網背後的三個服務（GitHub、Supabase、Google Cloud）。平常編輯內容完全用不到它，只有工程師處理問題時才需要。密碼社長保管，交接時一起交出去。

## 出問題

- **沒有權限**：請人去「管理員」加你的 email，確認沒打錯。
- **後台第一次開很慢**：正常，資料庫閒置會睡著，喚醒要幾秒。
- **發布了但官網沒變**：先強制重新整理（Mac：Cmd+Shift+R；Windows：Ctrl+F5），再看後台總覽的重建狀態。
- **重建失敗**：通常是暫時的，隨便找一個東西再按一次發布。連續兩次都失敗就截圖給工程師。
- **欄位標紅**：那格必填或格式不對，最常見是英文沒填、連結沒 https://。
- **不小心刪掉**：「已刪除」頁還原，再發布。
- **圖片傳不上去**：只吃 PNG、JPG、SVG。
- **整個官網打不開**：跟後台無關，看 https://www.githubstatus.com/ 有沒有掛，等一下就好。

找工程師的時候附上：你在哪一頁、做了什麼、截圖。

## 不要做的事

- 帳號不要借人。
- 已發布的專案／文章不要改網址代號。
- 不要去 GitHub 或 Supabase 直接改資料，那是工程師的地方。
- 週報 Prompt 產出的格式不對就改 Prompt，不要手動一格一格貼。
